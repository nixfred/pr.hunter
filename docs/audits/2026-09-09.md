# Grok audit and resolution — PR Hunter 1.0.1

Requested by the repository owner on 2026-09-09 before public release.
Grok Build CLI 1.0.25 used **grok-4.6-build** to review a source-only copy of
commit `884f967`. Gitleaks scanned that copy before submission. Credentials,
runtime state, private briefs and other projects were not part of the review.
The backend review used only a file-reading tool; the interface review used
its supplied source bundle. Grok did not implement changes or run tests.

Original reports: [backend](grok-backend.md), [interface and installer](grok-interface.md).
These are reviewer findings, including assumptions and false positives. The
resolution below takes precedence over the raw reports. The initial oversized
prompt and plan-mode attempts did not produce a complete backend audit; the
completed backend review was rerun with read-only tools and plan mode disabled.

## Confirmed findings addressed

| Finding | Resolution |
|---|---|
| Backend 1: permanently cached GitHub account | Refresh identity on force, on a five-minute TTL, and before preparing work; discard the previous account's cache after a switch. Handoffs fail if identity cannot be checked. |
| Backend 2, 8: stuck interrupted receipts and misleading cancellation | Recover `sending` as `uncertain`; acknowledge it explicitly without releasing deduplication receipts. Nonqueued cancellation says nothing changed. Save each queue result independently. |
| Backend 3: transient discovery cancels queued work | Incomplete/stopped-session discovery pauses missing projects. Confirmed closure still cancels; queues still expire after 24 hours. |
| Backend 4: one unavailable repo blocks the whole preview/handoff | Collect per-repository fetch errors. Show incomplete coverage in the UI, receipt and brief; assign only available items. Fail if every repository is unavailable. |
| Backend 6: network I/O holds dispatch lock | Fetch GitHub data outside the delivery lock; reacquire and recheck deduplication, project mapping, checkout and agent before creating a handoff. |
| Backend 10: malformed session aborts healthy discovery | Validate RPC/snapshot shapes; isolate per-session and per-workspace failures, including Git timeouts. Unknown prompt errors remain uncertain. |
| Backend 12: empty mapping selects caller cwd | Require an explicit nonempty checkout path. |
| Interface 1, 2: competing results and overlapping actions | One helper process; queue an action behind a scan, refresh after actions, and combine stdout/stderr/exit only when all finish. JSON success is not overwritten by unrelated stderr. |
| Interface 3: helper can leave UI permanently busy | A five-minute watchdog reports timeout and releases the UI. Saved receipts preserve ambiguous-send protection. |
| Interface 4–7: input/path handling | Normalize project arrays/defaults; decode file URLs; pass options as `--name=value`; guard unavailable services. |
| Interface 8–9: hidden results and busy buttons | Show scan errors alongside action messages; disable every action button while another action is pending/running. |
| Interface 10–11: needless installer edits / empty errors | Keep an already-installed configuration unchanged and report stderr, stdout or the exit code on failure. Retry failures retain their diagnostic. |

Additional fixes: every project row now opens its Herdr workspace, including
unmapped projects and projects without a single local agent. Existing terminal
windows are focused; unattached running sessions can be joined in a new terminal.
Dispatch focuses before contacting GitHub. Preview no longer needs an agent.
Brief writes are atomic and owner-only from creation. Queue signatures include
checkout roots and remote mappings. Labels distinguish open counts from the
historical handoff receipt. Two original README SVG graphics explain the flow.

## Findings checked but not applied as suggested

- **Backend 5:** a successful repository does not clear a preceding repository
  error in this code. Cached counts intentionally remain visible with an error
  indicator and per-repository timestamps; replacing them with zero would be
  misleading. Account switches now invalidate the old cache.
- **Backend 7:** the GitHub issues endpoint does return `draft` for PRs. A live
  response verified both `true` and `false`. Existing handling was correct;
  missing draft state is now explicitly unknown and review-only until verified.
- **Backend 9:** focus now happens before GitHub I/O. A failed Herdr focus remains
  a reason to stop an immediate handoff rather than silently assign work after
  the requested join failed. Compositor/terminal errors are reported separately.
- **Backend 11:** automatic deletion of briefs when a prompt is accepted would
  remove a file the agent may still need. Expiring deduplication records would
  make old item versions eligible again. Records are intentionally retained;
  automatic archival/retention management remains a future enhancement.
- **Interface 12:** the installed `WidgetButton` derives its implicit size from
  its label and bar metrics, independently of its anchored width/height. The
  proposed size cycle is not present; the actual widget renders correctly.
- Numeric pane IDs, non-line-delimited unsolicited replies, and `done` not being
  promptable do not match the installed Herdr protocol 20 schema/behavior.

## Remaining protocol limits

Herdr's `agent.prompt` accepts a target, text and optional wait. It has no
atomic expected-occupant/idle precondition. Identity/readiness checks immediately
before send reduce the window but cannot eliminate a replacement or state change
between separate requests. Unknown delivery errors never release receipts for
automatic retry. Native identity fields and snapshot responses were checked
against the installed schema and the isolated transport test.

GitHub pagination is a live view, not a transaction. Agents must refetch listed
items and skip anything already resolved, as every brief instructs. A receipt
proves prompt acceptance, not successful completion of repository work.
